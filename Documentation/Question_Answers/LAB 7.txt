1. In ALU with a = 200, b = 100, why is the Sign flag (S = 1) set for OR (236), XOR (172), and SHL (144)?

Answer:

The Sign flag (S) indicates the most significant bit (bit 7) of an 8-bit result.

In an 8-bit register, if the most significant bit is 1, the Sign flag is set to S = 1.

For the given operations:

OR = 236 = 0xEC
XOR = 172 = 0xAC
SHL = 144 = 0x90

All three results have their most significant bit set to 1.

Therefore, the Sign flag becomes S = 1 for all three operations.

This flag indicates the sign bit of the result, regardless of whether the value is interpreted as signed or unsigned.

3. Why do x / 8 and x >> 3 give the exact same answer for x = 17 (2) and x = -8 (-1), but differ for x = -17 (-2 vs. -3) and x = -1 (0 vs. -1)?

Answer:

Integer division (/) in C truncates the result towards zero.

For example:
17 / 8 = 2
-17 / 8 = -2
-8 / 8 = -1
-1 / 8 = 0

An arithmetic right shift (>>) moves the bits towards the right while preserving the sign bit for negative signed values.

For negative numbers, this generally produces a result equivalent to rounding down towards negative infinity on the ESP32.

For example:
17 >> 3 = 2
-17 >> 3 = -3
-8 >> 3 = -1
-1 >> 3 = -1

Therefore, division and right shifting produce different results for some negative numbers because they follow different rounding rules.

They give the same result for positive numbers and negative numbers that are exact multiples of 8.

This experiment shows why right shifting should not always be used as a replacement for division when working with negative integers.
