1. Through this experiment, I understood how the IEEE 754 standard represents floating-point numbers using three fields: 1 sign bit, 8 exponent bits and 23 mantissa bits in a 32-bit float. For example, the value -2.5 was represented as 0xC0200000, helping me understand how a decimal value is stored in binary.

2. I learned that computers cannot represent every decimal number exactly in binary. The value 0.1 is an example, and repeatedly using it in calculations can introduce rounding errors.

3. One of the most important observations was adding 0.1 one million times. The float result was 100958.34375000 instead of the expected 100000.00000000, whereas double produced 100000.00000133, which was much closer to the expected value. This demonstrated how precision affects accumulated calculations.

4. I also understood that floating-point precision becomes limited as numbers grow larger. When 1.0f was added to 2^24 (16777216.0f), the value stayed 16777216.0f because at that magnitude consecutive representable floats are spaced by 2.0.

5. This experiment helped me understand that the gap between two representable floating-point numbers increases as their magnitude increases. Therefore, even a small addition can become insignificant when working with sufficiently large values.

6. I compared the execution cost of 10,000 integer, float and double additions using the ESP32 cycle counter. The output showed approximately 11.1 cycles per int32 addition, 11.0 cycles per float addition and 68.3 cycles per double addition.

7. What surprised me most was that float and integer operations had almost the same execution cost, while double operations took considerably more cycles. This helped me understand the difference between single-precision hardware support and the additional processing required for double-precision calculations on this ESP32.

8. Overall, this experiment taught me that choosing a data type is not only about storing a value. It also involves considering numerical accuracy, precision limitations and processing performance. I was able to connect IEEE 754 representation and floating-point arithmetic with actual hardware behaviour through the ESP32.
